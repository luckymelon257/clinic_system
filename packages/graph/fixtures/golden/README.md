# Golden fixture — еталонні відповіді, пораховані вручну

Написано **до** коду рушіїв (`fn_trace_*`, Cypher). Гейт еквівалентності: PostgreSQL і Neo4j мають дати рівно
`expected.json` на цих даних, а потім однакові відповіді між собою на ×1 seed.

Завантаження: `migrate` (без seed-ів) → `psql -f fixture.sql` → (для Neo4j) повний ETL.

## Семантика (однакова для обох рушіїв)

- **Присутність** — рядок `v_presence` (ребро `PRESENT {f, t}`): напіввідкритий інтервал `[f, t)`; відкрите перебування `t = ∞`
  (`'infinity'` у PG, `9e15` у Neo4j). Прийоми зі статусом `cancelled` / `no_show` не дають присутності.
- **Вікно** `[from, to)`: присутність враховується, якщо `f < to AND t > from`.
- **Контакт (1 крок)**: дві різні особи, присутні в **одному місці** (кімната, палата або кабінет), обидві присутності
  враховані вікном і перетинаються між собою: `x.f < y.t AND y.f < x.t`. Інтервали, що лише торкаються
  (`x.t = y.f`), — не контакт. (За теоремою Геллі для відрізків це те саме, що непорожній перетин усіх трьох: x, y, вікно.)
- **Трасування** (`depth` 1…5): для кожної досяжної особи — **мінімальна** кількість кроків; сам індексний не повертається.
  Часова послідовність контактів не вимагається (D-25). Порівнюється множина `(kind, id, hops)`.
- **Шлях** (`maxDepth`): довжина найкоротшого ланцюга в кроках (особа → місце → особа = 1 крок) або `null`, якщо
  особи не пов'язані в межах `maxDepth`. Порівнюється лише довжина (найкоротших шляхів може бути кілька).
- **Взаємодії**: множина препаратів = `medicationIds` ∪ (якщо `patientId`) препарати, які пацієнт приймає в момент `at`
  (`f <= at < t`, ребро `TAKES`). Пара `(a, b)`, `a < b`, перевіряється, якщо хоча б один її кінець — у `medicationIds`.
  Рядок на кожне джерело: `direct` (пара в `medication_interactions`) і `class` — на кожну пару класів
  `(classA ∈ класи a, classB ∈ класи b)`, для якої є запис у `drug_class_interactions` (неорієнтовано; `classA = classB` —
  дублювання терапії). `classA` — клас препарату `a`.
